# 长篇网文创作技能

> 给中文长篇网文作者和 AI 写作 Agent 的通用技能。从开书定调、规划卷纲和章纲，到按章续写、校对和同步设定，都围绕同一本书的文风与已确认事实展开。

**技能名** `novel-workflow` · **技能入口** [SKILL.md](SKILL.md)

适用于支持 Agent Skills 的客户端，包括 **Codex、Claude Code、Google Antigravity 和 OpenCode**。能读取工作区文件的其他 Agent 也可以根据路径加载技能入口和配套资料。[Agent Skills 规范](https://agentskills.io/specification)

[适用场景](#适用场景) · [创作流程](#创作流程) · [目录结构](#目录结构) · [安装与调用](#安装与调用) · [使用示例](#使用示例) · [脚本用法](#脚本用法) · [常见问题](#常见问题)

## 适用场景

| 创作进度 | 可以交给技能的任务 | 产出 |
| --- | --- | --- |
| 只有书名、题材或一个开篇念头 | 初始化项目，确认视角、目标平台和文风 | 独立的项目目录、本书配置、文风锚点模板 |
| 手里已有样章或连载正文 | 提取本书声线，梳理现有目录与写作约定 | 文风摘要和语感样段，后续按本书约定接着写 |
| 有主线，还没排到每一章 | 按需要整理总纲、卷纲、细纲或指定范围的章纲 | 有明确因果、关键场面和章节落点的规划 |
| 节点已确定，需要写正文 | 根据现有章纲和上章结尾起草、续写或重写 | 章节草稿、字数核验及相关设定更新 |
| 作者已修过稿，需要再过一遍 | 校对指定词句、核对前后事实或对照两版正文 | 局部修改及必要的复核记录 |

叙事流程适用于不同中文网文题材。写番茄平台的重生或穿书系统文时，可补读开篇前因、系统能力边界与首轮收益的专项指南。[番茄重生系统文开篇与结构](references/番茄重生系统文开篇与结构.md)

## 创作流程

```text
书名与题材 / 已有书稿
  │
  ├── ① 确认项目与任务范围
  │      建立或读取本书配置、创作入口和文件目录
  ├── ② 设置文风锚点
  │      自写样章 / 外部参考 / A/B 试写 / 先按题材基调推进
  ├── ③ 排纲
  │      确定起因、关键场面、章节落点与下章期待
  ├── ④ 两遍式正文
  │      Pass 1 按本书声线起草 → Pass 2 回读、核对事实与字数
  └── ⑤ 归档与接续
         记录本章结果，更新人物、能力、物品和资源账
```

### 1. 先锁定一本书

新建书时，Agent 建立本书的 `AGENTS.md`、独立技能目录和创作文件夹。已有连载按书名或路径定位项目，读取作者当前用的章纲、正文和设定。需要只校对某个片段时，可以在指令里直接指定文件和范围。[新书初始化清单](references/新书专属化.md)

材料发生冲突时，按**作者最新要求与手改正文 → 当前有效章纲 → 细纲 → 总纲 → 待校准设定 → AI 草稿**核对事实。哪一份文件被作者定为最新版本，会影响后续章节依据。

### 2. 用文风锚点定声线

新书初始化后，Agent 会先询问作者如何定调。可以按手里的材料选择。

| 方式 | 怎么做 | 写入文风锚点的内容 |
| --- | --- | --- |
| 提供自写样章 | 上传或粘贴满意片段，约 500–3000 字即可 | 保留作者的句式、断行、对白与情绪，摘取代表段落 |
| 提供外部参考 | 给出参考作品的 TXT、Markdown 或片段 | 提炼叙述视角、节奏和信息密度，用本书情境重构原创样段 |
| 试写 A/B 两版 | 围绕同一个开篇冲突，各试写约 500 字，再挑选或手改 | 记录作者选中的口吻和片段 |
| 先按题材推进 | 告诉 Agent 暂缓配置，之后再补样章 | 记录当前基调和待补的文风状态 |

配置完成后，本书的锚点会记录**节奏与情绪张力、旁白口吻、2–3 段代表性的语感样段**，需要时补充改写对照。进入正文工序时读取这些样段，后续可用作者认可的定稿片段更新。[文风锚点与自动入库](references/文风锚点与自动入库.md)

### 3. 用留白章纲锁定因果与结果

章纲用完整句子写清人物想做什么、为什么行动、会遇到什么阻力，以及本章结束时实际有什么变化。确定这些信息后，把具体对白、停顿和动作节奏留给正文。设计重要反转或推进卡住时，可按需翻查技法目录。[章纲模板](references/章纲模板.md) · [实战技法速查](references/实战技法速查目录.md)

以一章都市悬疑为例。

| 章纲锚点 | 示例 |
| --- | --- |
| 起因与切入 | 上章末尾，守档员林岑发现一张三年前已注销的借阅单出现在今晚的交接册里。她要在换班前查清是谁重新登记的。 |
| 核心推进与关键场面 | 值班主管起初以记录已封存为由拒绝查阅。林岑找到馆规里的交接条款，指出今晚的记录仍须由她签字，争取到当面核对登记簿的机会。 |
| 落点与变化 | 林岑查出登记用的是已离职前任的工号，拿到登记页的复印件。主管把她的查阅记入正式交接记录，此事天亮后会被馆长看到。 |
| 下章期待 | 复印件上的寄送地址指向林岑小时候住过的那栋楼。她必须赶在馆长上班前决定要不要去一趟。 |

### 4. 两遍式写正文

#### Pass 1 · 作家态起草

起草前读取**本书配置和文风锚点、当前有效章纲、上一章最新正文末尾约 100 字，以及本章会用到的设定和资源账**。从上一章留下的动作、回应或后果接起，把人物的目标、利益冲突和关键选择写进场面。

章纲确定的结果和人物知情边界需要兑现。对白、情绪烈度、短句断行、动作快慢可以随题材和场面发挥。默认每章至少 **1700 个有效汉字**，本书已有篇幅约定时按该约定执行。[正文创作指南](references/good-writing.md) · [口吻、情绪与叙事节奏](references/口吻、情绪与叙事节奏.md)

#### Pass 2 · 轻量品控

| 核对项 | 怎么检查 |
| --- | --- |
| 故事是否读得懂 | 按第一次读正文的视角，核对人物关系、行动前因、破局依据、实际收益和结尾留下的问题 |
| 事实是否接得上 | 核对时间、地点、角色知情范围、能力边界与物品去向 |
| 篇幅是否达标 | 按章运行字数脚本，用有效正文汉字数与本书底线比较 |
| 词句是否需要修 | 按需定位语病、歧义、机械重复或可能的事实越界，再结合上下文处理 |

词句校对保留原稿里成立的人物口吻、内心反应和情绪力度。要求只修局部时，以指定原稿为底改动相应词句。[情绪保留式改稿](references/情绪保留式去AI.md) · [表达规范库](references/表达规范库/README.md)

### 5. 归档结果，接下一章

章节落盘后，提取正文明确发生的人物、能力、物品与资源变化。章节归档用一句话写清本章实际发生了什么，细节写入人物卡或相应账本。后续规划中的事实标记为规划态，正文初稿按草稿管理。作者认可的写法和具体避坑经验可记入本书的 `改稿经验.md`。[正文同步与衔接](references/同步流程.md)

```text

    ├── references/
    │   ├── 本书配置.md
    │   ├── 本书文风锚点.md

```

同一个工作区放了多本书时，在每次任务里写明书名或路径。每本书的文风锚点、专属规则和进度都从它自己的目录读取。

## 安装与调用

### 工作区安装

从你准备在 Agent 中打开的工作区根目录开始。选择对应的技能目录，保留完整的 `novel-workflow/` 文件夹，让 `SKILL.md`、`references/` 和 `scripts/` 处于同一层级。

| 客户端 | 安装目录（相对于工作区根目录） | 指定技能的方式 | 官方说明 |
| --- | --- | --- | --- |
| Codex | `.agents/skills/novel-workflow/` | 在消息里引用 `$novel-workflow` | [Codex 技能文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) |
| Claude Code | `.claude/skills/novel-workflow/` | 输入 `/novel-workflow`，接上具体任务 | [Claude Code 技能文档](https://code.claude.com/docs/en/skills) |
| Google Antigravity | `.agents/skills/novel-workflow/` | 在 App 或 CLI 里输入 `/novel-workflow` | [Antigravity 技能文档](https://antigravity.google/docs/skills) |
| OpenCode | `.agents/skills/novel-workflow/` | 在提示词里要求加载 `novel-workflow` 技能 | [OpenCode 技能文档](https://opencode.ai/docs/skills/) |

使用 **GitHub CLI** 时，按客户端选择一条命令。

```sh
# Codex、Google Antigravity 或 OpenCode
gh repo clone 20321231788a-cmyk/novel-workflow .agents/skills/novel-workflow

# Claude Code
gh repo clone 20321231788a-cmyk/novel-workflow .claude/skills/novel-workflow
```

使用 **Git** 也可以克隆。下面以 `.agents/skills/` 为例，Claude Code 用户将目标路径换成 `.claude/skills/novel-workflow`。

```sh
git clone https://github.com/20321231788a-cmyk/novel-workflow.git .agents/skills/novel-workflow
```

也可以下载主分支 ZIP，解压后将目录改名为 `novel-workflow`，放入上表对应位置。[下载 ZIP](https://github.com/20321231788a-cmyk/novel-workflow/archive/refs/heads/main.zip)

安装完成后，在客户端打开这个工作区。目录装在 `.agents/skills/` 且通过 Git 克隆时，可用 `git -C .agents/skills/novel-workflow pull --ff-only` 更新公共技能。更新书内专属副本时，按本书已有规则与文风配置合并。

### 直接让 Agent 读取文件

其他可以访问工作区的 Agent，可把完整目录放在 `tools/novel-workflow/`，然后在提示词里指定技能入口。有本书专属技能时，也可以直接指向书内入口。

> 请读取 `tools/novel-workflow/SKILL.md`，按任务选择它引用的文件。当前项目是《雾灯档案》。先确认本书的项目目录、写作约定和当前章纲，再帮我规划第 7 章。

创建或修改项目文件需要客户端的工作区写入权限。文风分析、字数核验和稿件对比使用 Python 标准库，表达扫描使用 Node.js。运行脚本时需要 Agent 能调用终端，或由作者在本地运行。

## 使用示例

下列提示词可以直接复制，再换成自己的书名、路径和章节编号。已在客户端挂载技能时，也可以用上表的调用方式。

### 新建一本书

> 使用 `novel-workflow` 初始化《雾灯档案》。题材是都市悬疑，采用第三人称限知视角。主角是夜班档案管理员，开篇发现一张被注销的借阅单重新出现在交接册里。请先建项目和本书配置，建好后让我选择文风锚点。

### 根据样章设置文风

> 使用 `novel-workflow` 读取《雾灯档案》的 `参考资料/作者样章.md`。这是我自己写的，帮我提炼叙述视角、句子呼吸、对白和心理活动的衔接方式。选 2–3 段最能代表口吻的原稿，写入本书文风锚点。

### 只排指定章节

> 使用 `novel-workflow` 根据《雾灯档案》的现有细纲排第 7–9 章。每章写清直接起因、角色的关键选择、局势变化和下章期待。登记人的真实身份第 9 章仍处于待查状态，具体对白留给正文。

### 接着上一章写

> 使用 `novel-workflow` 接着《雾灯档案》第 6 章最新正文的结尾，按已确认的第 7 章章纲写正文。重点写林岑与主管的交接对话。写完核对谁知道前任工号、复印件最后在谁手里，并检查章长。

### 为作者定稿做一次词句校对

> 使用 `novel-workflow` 校对 `雾灯档案/正文/第007章.md` 的交接场景。只处理病句、搭配和指代不清，保留林岑的心里话、对白顺序和语气。发现剧情疑点时，把位置和原因标给我。

## 脚本用法

在已初始化的**本书根目录**运行下列命令，把示例文件名换成手头的样章或正文。报告路径位于 `写作校验/`。

**分析文风样本**

```sh
python -X utf8 "skills/novel-workflow/scripts/analyze_style_sample.py" "参考资料/作者样章.md" --output "写作校验/样章分析.json"
```

报告里的句长、段长和对白分布用于观察节奏，文风锚点仍以样段的实际阅读感受为准。

**核验章节字数**

```sh
python -X utf8 "skills/novel-workflow/scripts/check_chapter_length.py" --min-han 1700 "正文/第007章.md"
```

脚本接受 UTF-8 的 Markdown 或 TXT，按独占一行的「第7章」一类章标题分段。统计有效正文汉字时，脚本跳过章标题、章前说明、围栏和明确标记的作者说明。正常对白和系统记录按正文统计。

**按需扫描表达问题**

```sh
node "skills/novel-workflow/scripts/check-ai-patterns.js" --check --json --library-dir "skills/novel-workflow/references/表达规范库" --output "写作校验/第007章表达扫描.json" "正文/第007章.md"
```

报告会给出候选位置和规则。打开对应正文，核对上下文后再决定是否修改。

**对比两个稿件**

```sh
python -X utf8 "skills/novel-workflow/scripts/compare_drafts.py" "正文/第007章-初稿.md" "正文/第007章-改稿.md" --output "写作校验/第007章稿件对照.json"
```

对比报告列出章号对齐情况以及字数、段落和标点变化。情节是否被改动需要对照两版内容复核。

## 常见问题

### 已经在连载，怎样接入？

把项目路径、作者最新正文、有效章纲和设定文件交给 Agent。请它先定位本书现有规则，沿用现在的目录和章节编号，再做你指定的规划、续写或校对。

### 没有样章，可以直接开书吗？

可以。建书后选择 A/B 试写，或者选择先按题材基调推进。之后有了满意的手改稿，再补到本书文风锚点。

### 字数检查为什么没有数到某章？

检查文件是否使用 UTF-8，以及标题是否独占一行并包含章号，例如 `## 第7章 迟到的回执`。合订稿里每章都要有自己的标题。脚本也会报告重复章号和未闭合的围栏。

### 公共技能更新后，怎么用到已经建好的书？

从公共版对照新增规则或工具，按需要合并进本书的 `skills/novel-workflow/`。新章节继续读取这本书的配置、文风锚点与最新设定。
